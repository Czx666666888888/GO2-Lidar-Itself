# blue_cube首个训练项目

目标按用户说明为5×5×5 cm蓝色立方体。`data.yaml`中的类别仅是此项目配置，
训练代码和ROS节点均不依赖该名称。

当前没有人工审核的YOLO检测标签，因此**尚未训练blue_cube模型，无真实mAP结果**。
现有HSV检测输出不作为真值。

## 已整理素材

2026-11-09盘点camera_ws/records：30份mp4中有10份`*_raw.mp4`，共3117帧、207.8秒，
640×480、名义15 FPS。按每秒一帧提取213张图片到本机pool/images，manifest保留
原视频路径、源帧号、视频内秒数；全部reviewed=false，没有生成标签。
视频时长由容器帧数/FPS计算，不宣称每个历史原始视频已在本任务完整解码验收。
源视频清单见[sources.json](sources.json)，原始媒体和图片未提交Git。

本轮查看每段10%/50%/90%位置的30张抽样画面：可见单个立方体、上缘/下缘出画、
地砖反光及线缆；近/远与模糊片段可供人工挑选。抽样不是逐帧身份/距离或光照标注。
这些连续实验背景相近，暂全部归为`lab_floor_20261108_09`同一组，不强行随机划分。
目前没有人工给定low_light/edge/motion_blur等场景tags，不发布任何困难分组结果。

缺少的素材/审核：

- 所有213张的人工框、漏标复核和背景负样本确认。
- 至少两个额外独立拍摄组，形成具有独立场景的train/val/test；不要把这些相近视频
  按文件名随机分开，充当独立评估集。
- 多个物块同时出现、不同背景/光照的系统覆盖。
- 蓝墙/蓝色线缆等干扰物独立负样本；目前抽样看到线缆，但不足以声明蓝色线缆覆盖。
- 明确光照条件的弱光组、运动模糊标注、左右/上下边缘、不同实测距离分组。
- 后续连续漏检评估所需的逐帧可见性/目标身份时间线。

更早20份带检测叠加的mp4不能默认当干净训练RGB，尤其曾有mask tile遮挡右下角。
优先查找对应原始流/rosbag；不要用被覆盖像素推断真实标签。当前不需要安排大量新
实机运动，先标注现有原始数据，再按缺项安排少量独立静态/手持场景采集即可。

若pool已存在，不重复抽帧；审核完成后按总README操作。正式比赛目标建立新目录，
不要覆盖此数据集或复用本项目类别名称。
