# Full 自动录像

来源：2026-11-15 集成分支源码与离线测试。本轮未连接设备采集、未部署、未使能或运动。
真实双相机连续采集、深度质量与录像负载影响均 **NOT VERIFIED**。

仍用原入口，无需额外录像命令；`--view`仅控制桌面预览，不控制是否保存：

```bash
bash go2_test.sh --execute --mode full --view
```

## 保存内容和位置

PC主仓库 `camera_ws/records/full_<时间戳>/` 下：

- `approach_*.mp4`：前侧D435搜索至停靠结束的识别/控制叠加画面。
- `approach_*_raw.mp4`：对应原始RGB；JSONL保存原图时间戳及检测/控制记录。
- `recordings.json`：前侧录像索引，以及本轮D455的状态、远端位置、复制结果。
- `wrist/grasp_<时间戳>_<随机后缀>/d455_raw.mp4`：实际进入机械臂抓取任务后，
  从原抓取回调开始前直到回调结束的连续腕部RGB，覆盖展开、观察、抓取、放置及返回。
  `frames.jsonl`保存帧号、相机时间戳/时钟域、主机时间；`recording.json`保存完成/错误信息。

前侧沿用原录像生命周期，在导航停靠收尾关闭，不声称覆盖后续趴下/抓取时段。
预检失败尚未启动录像时不会生成视频；停靠失败不会进入抓取，D455标为NOT STARTED。
视频采用名义帧率播放，实际采集间隔以JSONL为准；不把视频播放时长当作真实动作时长。

## D455单一所有者

录像在原S1服务的抓取工作循环内启动，绑定原wrist配置中的序列号和RGB-D格式。
只有一个RealSense pipeline、一个采集线程；原抓取RGB-D快照借用该线程的新帧，
保留原对齐、深度融合、warmup、质量阈值和轨迹/安全检查，不额外启动ROS D455驱动。
普通独立快照在无录像上下文时仍按原行为打开/关闭自己的pipeline。
连续保持相机流与此前分段开关流的实机差异尚未验证，不声称图像/时序效果完全相同。

相机启动或录像文件打开失败会阻断本次抓取回调；执行中录像I/O失败记录错误，
不从录像线程发运动/恢复命令，保留原抓取故障与保持策略。
正常和异常回调均在finally中封口；记录writer提交帧数、容器帧数及首帧可解码检查。
`complete`仅表示录像检查结果，`task_error`单独记录抓取错误，不代表抓取或放置成功。

远端原件保存在 `/home/unitree/s1-arm-control-v2/data/grasp_videos/`，不自动删除。
PC收尾仅复制本轮新增且已封口的目录，不复制上一轮旧录像；复制失败标记REMOTE_ONLY并保留路径。
断网/任务仍运行时，未封口内容不会被伪称保存完成，需要恢复连接后取回。

## 一次性兼容层升级

新兼容版本 `v2_usb01_feedback_video_3` 只在无S1串口所有者时安装。
已运行的旧版本不会被热替换或自动停止；full复用前校验版本，旧版明确阻断，
由操作者确认支撑并按既有停机路径退出旧保持后，再用原入口启动。
原ZIP可用时照原方式校验/生成补丁；本地ZIP缺失而远端已部署v2时，
读取远端原始备份并逐文件对照原SHA256SUMS恢复所需源文件，再生成同一兼容补丁。
未知改动或hash不符仍保留现场并停止，不覆盖第三方未知版本。
